# 自動応答の返答判定の見直し

## Why

自動応答チャンネルでは、メンションの無い発言に返答するかを判定モデル Jev（`typesafe/jev-1.14`）が決める。
返答するのは、返答すべき確率（`noul`）がしきい値 `REPLY_GATE_THRESHOLD`（v1.15.0 の既定は 0.3）以上の発言である（`src/services/replyGateService.ts` の `judge`）。
2026-10-17 の本番のスレッドでは、21 件の判定がすべて返答になり、bot は人どうしの会話、独り言、bot への制止にも割り込んだ。

21 件を下の「本番の判定」の表のとおり分けると、返答すべき 9 件の `noul` はすべて 0.74 以上で、黙るべき 12 件のうち 9 件は 0.32〜0.48 に集まっている。
この分布から読み取れる原因は四つある。

1. しきい値が低い。表の値では、しきい値が 0.5 なら黙るべき 12 件のうち 9 件が黙り、返答すべき発言の取りこぼしは無い。0.5 以上に残る黙るべき発言は、0.50 ちょうどの 20 を含めて 3 件である。
2. 判定の問い（`buildReplyGateQuestion`）の黙る側の基準に、「bot に黙るよう求める発言」が無い。bot への制止は bot を「お前」と呼ぶので、返答する側の基準「bot に向けた発言」に当たる。黙る側には「bot の回答への礼や人どうしの反応」が既にあるが、bot の返答を受けて人どうしで話した 11 と 14 は 0.85 と 0.77 になった。返答する側の「bot の直前の回答への続きの質問」に寄せて読まれた可能性がある（推測）。
3. 返答を生成するモデルには、今回の発言が判定を通って選ばれたことも、自分が今後の返答を制御できないことも、専用の指示で伝えていない（`src/services/chatService.ts` の system 指示の組み立て）。この会話では、bot は独り言のメモにも依頼として答え、仕組み上守れない「今後は呼びかけられたときだけ返します」という約束もし、返答は「ほかの話題も気軽に投げてください」のような誘いで終わることが多かった。会話の冒頭で自動応答のテストだと書かれていたので、指示が無いことがこれらの原因だとは確かめられない。指示を足すことで減るかは仮説として扱う。
4. bot が毎回返答するので、新しい発言の直前は常に bot の返答になり、次の人の発言が bot への続きとして読まれやすくなる（推測。判定の状態の組み立てと問いの文面から）。原因 3 の誘いの言葉は、この傾向を強めている可能性がある。

このスレッドはテストのための会話で、最初の発言が bot の介入を促している。
話題の多くは bot 自体についてで、参加者は 2 人なので、21 件は普段の雑談より判定が難しい側に偏っている。

## 依存 / 関連 change

- 先行（実装済み）: reply-gate（v1.15.0）— 本 change はその判定の問い、状態、しきい値を見直す
- 先行（実装済み）: [author-identity](../author-identity/design.md) — 判定に渡す発言者の名前を `表示名 (@ユーザー名)` の形にした。名前の形が変わると `noul` も変わりうるので、しきい値と問いの測定はこの形で行う

## Goals / Non-Goals

**Goals:**

- bot について人どうしで話している発言、bot への制止、独り言に返答しないようにする
- 判定を通って返答するときに、bot が守れない約束をせず、返答を誘う言葉で締めないようにする
- しきい値と判定の問いを、手書きの例と本番から作った例の両方で組にして測り、決める

**Non-Goals:**

- メンションされた発言の扱い。今までどおり必ず返答する
- 判定を通さない自動応答（判定が無効、または無料モデルのみの guild）の挙動

## Decisions

| 判断事項 | 選択 | 理由 |
| -------- | ---- | ---- |
| しきい値 | 既定値を 0.4 にする（`src/config/envVars.ts`。`.env.example` と README は `scripts/generate-readme.ts` がそこから生成する） | 下の「測定と採否」の比較で、返答すべき判定の取りこぼしと制止への返答を 0 に保ったまま、黙るべき判定への返答が最も少ない組である。0.5 は、手書きの返答すべき例を 1 回ごとの判定で取りこぼす（例を 81 件にした測定では 0.42〜0.49 の 3 件）。今の問いのままで上げられないのは、返答すべき例の最小が 0.38 で、0.4 で取りこぼすからである |
| 判定の問いの黙る側の基準 | 「${botName} に黙る、口を挟まないよう求める発言（${botName} に向けていても黙る）」「${botName} に答えを求めず、${botName} の仕組みや挙動について人どうしで推測や感想を述べる発言」「独り言やメモ」を足す。${botName} の能力を直接問う疑問は返答する側に残す | 原因 2 に当たる。制止は bot に向けた発言の形をとるので、黙る側を優先すると明記しないと、1 つの問いの中で返答する側の基準と重なる。bot についての発言は、bot に答えを求めているか、人どうしで推測や感想を述べているかで分け、語尾（〜かな、〜かも、疑問形）は補助の手がかりとする。足した後は、制止への返答がどのしきい値でも 0 になった。制止に返答しないことで、bot が「黙ります」と約束する場面自体が無くなる |
| 判定の問いの返答する側の基準 | 変えない | 「${botName} の直前の回答への続きの質問」を「${botName} に答えや作業を求める、または ${botName} の回答への指摘、訂正、理解できないという反応を伝える、直前の回答への続き」に狭める案を測った。11 と 14 は下がらず、制止への返答が 0.4 で 2〜3 回に戻った |
| 判定を通った返答への指示 | 判定を通った発言（判定が失敗して返答に倒した場合を含む）への返答にだけ system 指示を足す。内容は、この発言は bot に向けたものではない可能性があること、返答を誘う問いかけで締めないこと、今後の返答のしかたを約束しないこと。会話履歴の有無にかかわらず付ける | 原因 3 と 4 に当たる。返答するかは判定が決めるので、モデルが約束しても守れない。返答の長さは指示しない。判定を通った発言には「一番古い発言を引用して」のような正当な依頼も含まれ、長さを縛るとその返答が損なわれる。メンションされた発言には足さない。指示で約束や誘いが減るかは仮説で、手動確認とリリース後の本番の返答で見る |
| 自動応答で返した印 | 判定の状態で、判定を通って返した bot の返答を `${botName}（自動応答）` と書く。どの返答が判定を通ったかは、`ReplyGateService` が判定を通した発言の ID（判定が失敗して返答に倒した発言を含む）を、黙らせた発言と同じく 1 時間メモリに持って決める | 原因 4 に当たる。同じ問いと 0.4 で印の無い組と比べ、元の文面で黙るべき判定への返答が 13 回から 10 回に減り、毎回黙った黙るべき発言が 7 件から 8 件に増えた。メンションの有無ではなく判定を通ったかで決めるのは、名前で呼ばれた発言（本番の 1）も判定を通るからで、印の意味は「呼ばれたか」ではなく「bot が自分の判断で返したか」とする。1 時間より前の返答には印が付かないが、窓が扱う会話も 1 時間以内なので（`WINDOW_RAW_AGE_MS`）、影響は返信先として状態に入る古い返答に限られる。返答の記録（`reply_records`）に列を足す案は、再起動後も印が残るが、スキーマ変更に見合わない |
| 自動応答を一時停止する tool | 採らない | 制止は判定の問いで黙らせるので、モデルに届かず tool が呼ばれない。届いた場合も、本番のスレッドでは 15 の制止の 22 秒後に別の参加者が bot に質問しており、1 件への叱責を一定時間の停止と読むと正当な返答まで消す |
| モデルに黙ることを選ばせる案 | 採らない | 「生成中...」を先に送るので、黙ると表示が出て消える。生成の費用は 1 件およそ $0.0009 で、判定（およそ $0.0001）の約 10 倍かかる（2026-10-17 の本番の値） |
| 判定を複数の問いに分けること | 採らない | 1 回の Decisions API の呼び出しで、返答すべきかに加えて「bot に答えや作業を求めているか」を聞き、両方がしきい値以上のときだけ返答する、2 つ目の問いだけで決める、2 つの平均で決める、の組み合わせ方を、しきい値と印の有無を合わせて 46 通り測った。元の文面で毎回黙る黙るべき発言を 9 件以上にすると、どの組み合わせでも手書きの返答すべき判定を 3 回以上取りこぼした。2 つ目の問いが、bot への依頼の一部まで黙る側に寄せるためである |
| 本番の判定を評価の例にすること | 下の表の 21 件を、言い換えた文面で `scripts/reply-gate-thread-cases.ts` に置く。採否は、手元に残した元の文面の 21 件と手書きの例で決め、言い換えた例の結果は再現用の参考として並べる | 言い換えるのは利用者の発言をリポジトリに残さないためである。言い換えた例を元の文面と例ごとに `noul` の平均 0.05 以内に揃えてから採否に使う方式は採らない。各例はそれより前の発言をすべて履歴に持つので、1 行を言い換え直すと後ろの例の値も動き（12 を直すと、文面の変わらない 21 が 0.27 から 0.39 になった）、同じ文面でも実行ごとに平均が 0.04〜0.05 揺れるので、揃えることができない（2026-10-18 に確かめた）。言い換えた例は、元の文面と同じ組で同じ傾向を示した（下の表） |

### 測定と採否

2026-10-18 に、`bun scripts/reply-gate-eval.ts --runs 3 --thresholds 0.3,0.4,0.5 --originals <元の文面>` で測った（`typesafe/jev-1.14`）。
判定は本番と同じく 3 秒で打ち切り、打ち切りとエラーは返答として数えた（どの組でも 0 件だった）。
判定の所要時間は、どの組でも中央値 270〜300ms、90 パーセンタイル 290〜320ms だった。
しきい値は `noul` を変えないので、各例を 3 回判定した結果に 0.3、0.4、0.5 を当てて数えた。

採否の基準は次のとおりである。

1. 返答すべき例（手書きと元の文面）の判定が 1 回でもしきい値を下回る組は除く。
2. bot への制止の例（12、15、21）の判定が 1 回でもしきい値以上になる組は除く。
3. 元の文面の黙るべき 12 件のうち、3 回ともしきい値を下回る件が 9 件に満たない組は除く。
4. 残った組の中で、黙るべき判定への返答の回数が最も少ない組を採る。

基準 1 から 3 をすべて満たす組は無く、基準 1 と 2 を満たす組のうち基準 3 に最も近い組を採った。
採った組の元の文面での結果は 8 件で、基準 3 に 1 件届かない。
残る 4 件のうち 11（0.73〜0.75）と 14（0.63〜0.69）は、bot の返答を受けて人どうしで意見を述べた発言で、問いの文面でも 2 つ目の問いでも下がらなかった（原因 4）。
20（「要改善事項」、0.42〜0.46）と 6（0.40 前後）は境目にある。

| 組 | 返答すべき判定の取りこぼし（手書き / 元の文面） | 制止への返答 | 元の文面で毎回黙った黙るべき発言 | 黙るべき判定への返答（元の文面） | 言い換えた例で毎回黙った黙るべき発言 |
| --- | --- | --- | --- | --- | --- |
| 今の問い、0.3（v1.15.0） | 0 / 0 | 9 | 0/12 | 35/36 | 1/12 |
| 今の問い、0.4 | 1 / 0 | 6 | 2/12 | 30/36 | 1/12 |
| 黙る側の基準を足す、印なし、0.4 | 0 / 0 | 0 | 7/12 | 13/36 | 8/12 |
| 黙る側の基準を足す、印あり、0.4（採用） | 0 / 0 | 0 | 8/12 | 10/36 | 8/12 |
| 黙る側の基準を足す、印あり、0.5 | 2 / 0 | 0 | 10/12 | 6/36 | 10/12 |
| 両側の基準を変える、印なし、0.5 | 0 / 0 | 0 | 8/12 | 12/36 | 6/12 |

表の値は、候補の組を同じ手書きの例 77 件で比べた一連の測定のものである。
採用した組は、語尾だけで判定していないかを見る対の例 4 件を手書きの例に足してから、もう一度測った（手書きの例 81 件）。
返答すべき判定の取りこぼしと制止への返答はどちらも 0 で、元の文面で毎回黙った黙るべき発言は 8/12、黙るべき判定への返答は 12/36 だった。
足した 4 件は、どれも正解の側に出た。
手書きの例の返答すべき判定の最小は 0.42 で、手書きの黙るべき判定への返答は 123 回中 6 回だった（v1.15.0 の組では 117 回中 15 回）。
両側の基準を変えた 0.5 の組は、元の文面で黙るべき判定への返答が 12 回で、採用した組（10 回）より多い。

過去の状態を固定して判定し直す評価では、bot が黙った後に次の発言の直前が人の発言になる効果は測れない。
原因 4 への効果は、リリース後の本番のログで見る。

### 正解の付け方

正解は、誰に向けた発言か、bot に答えや作業を求めているか、人の側で引き取る意思を示しているかで付ける。
語尾（〜かな、〜かも、疑問形）は補助の手がかりで、それだけでは決めない。

- bot に質問、依頼、指摘をしている発言は返答とする。
- bot について、または bot の返答を受けて人どうしで話している発言は、bot の名前や「お前」を含んでいても黙るとする。2 と 3 は bot の仕組みについての推測を場に述べたもので、bot に答えを求めていないので黙る。16 は bot の能力を bot に直接尋ねているので返答とする。
- bot に黙るよう求める発言と、独り言やメモは黙るとする。8 は「よく分からない」という反応を含むが、続けて自分で直すと述べており、人の側で引き取っているので黙る。
- 11、14、20 は、bot がそれに返答した直後に、発言した本人が 12、15、21 で bot を制止している。11、14、20 を黙るとする根拠である。
- 4 と 19 は、どちらも bot の返答への突っ込みで、上の規則だけでは決まらない。4 は bot の説明を受けて人どうしで笑っている発言として黙るとし、19 は bot の返答の矛盾を bot に指摘している発言として返答とする。この 2 件は運用の方針として付けた正解であり、19 の後に制止が無いことは、返答が望まれていた証拠ではない。

手書きの例には、語尾だけで判定していないかを見るために、bot に向けた「〜かな」の質問（返答）と、人に向けた直接の疑問（黙る）を対にして足す。

### 変更対象ファイル

- 修正: `src/services/replyGateService.ts` — 判定の問いの黙る側の基準を足す。判定を通した発言の ID を 1 時間持ち（`wasAnswered`）、判定の状態で、判定を通って返した bot の返答を `（自動応答）` 付きの名前で書く（`buildReplyGateState` の `isAutoReply`）

- 修正: `src/services/chatService.ts` — `autoReply` のときだけ、判定を通った返答への system 指示を足す
- 修正: `src/config/envVars.ts` — `REPLY_GATE_THRESHOLD` の既定値を 0.4 にする
- 修正: `scripts/reply-gate-eval.ts` — 例の集合（手書き、言い換えた本番、手元の元の文面）ごとに集計し、1 回の判定結果に複数のしきい値を当てて数える。判定を 3 秒で打ち切り、打ち切りとエラーを返答として数える。bot の返答は、直前の発言が bot へのメンションを含まなければ自動応答として印を付ける

- 修正: `scripts/reply-gate-cases.ts` — スレッド形式の例を評価の例に変える `casesFromThread`、制止の例の印、語尾の対の例

## Open Questions / Risks

- bot の返答を受けて人どうしで意見を述べた発言（本番の 11、14）には、まだ返答する。問いの文面でも 2 つ目の問いでも下がらなかったので、別の手段が要る。候補は、bot が自分の判断で返した直後の発言だけ、一時的にしきい値を上げる案である。リリース後の本番のログで、この種の発言がどれだけ返答されているかを見てから検討する。
- しきい値を上げると、評価の例に無い種類の返答すべき発言を落とす可能性がある。リリース後も、本番のログで `noul` が 0.4 の近くにある判定を確かめる。
- e2e のテスト用 bot は必ずメンションするので、判定を通る経路は e2e で通らない。判定と system 指示の効果は、評価のスクリプトと手動確認で見る。
