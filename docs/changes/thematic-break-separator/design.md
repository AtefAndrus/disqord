# 回答の区切り線を Separator で描く

## Why

Discord の Markdown は区切り線（`---`、`***`、`___` だけの行）を描かないので、モデルが回答に書いた区切り線はそのまま文字で表示される。
Components V2 には区切り線を描く Separator があるので、回答の区切り線はそれで描く。

## Decisions

| 判断事項 | 選択 | 理由 |
| -------- | ---- | ---- |
| 変換する範囲 | ページに分ける前の回答全体で、コードブロック（CommonMark の `` ``` `` と `~~~` の fence）の外にある、`-`、`*`、`_` のどれか 3 つ以上だけの行を区切り線とみなし、`---` と同じ 3 文字の印の行に置き換える。各ページではその印で前後を別の TextDisplay に分け、間に divider 付きの Separator を置く。先頭、末尾、連続した区切りで空になる部分は捨てる | Markdown の区切り線と同じ形だけを拾う。文の途中の `---` は変えない。コードブロックはページをまたぐことがあり、ページ単位では中にいるかを判定できないので、分割の前に判定する。印を `---` と同じ字数にするので、上限を超えた分を `---` に戻してもページは分割で測った字数を超えず、区切り線の行は本文を持たないので、ページの境目で切れても失う内容が無い。元の書き方（`***` など）は残さないが、Discord はどれも描かないので見た目は変わらない |
| 1 ページの上限 | 1 ページで Separator にするのは 8 本までとし、それを超えた区切り線は `---` の文字にする。空になって捨てた区切りは数えない | 区切り線 1 本で Separator と TextDisplay の 2 部品を使い、Discord の 1 メッセージ 40 部品の上限に近づく |
| ページの境目の区切り線 | ページの先頭か末尾に来た区切り線は捨てる | ページが分かれること自体が区切りになる。履歴には `---` として残らないが、段落の区切りが 1 本減るだけである |
| footer との区別 | footer の前の Separator は divider を持たないので、会話の履歴の読み取りと e2e は `divider: false` の Separator だけを footer の区切りとみなす。divider 付きの Separator は、履歴に `---` として読み戻す | 区切り線が回答の末尾近くにあっても、その後の段落を footer と取り違えない |

## Open Questions / Risks

- **私用領域の文字**: 印に U+E000 を使うので、モデルが U+E000 を 1〜3 個だけ並べた行を書くと、その行は捨てられるか区切り線になる。U+E000 には標準の字形が無く、回答にその行だけが現れることはまず無いので、エスケープはしない。
