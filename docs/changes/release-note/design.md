# /release-note

## Why

bot が新しい版で動き出しても、サーバーの利用者は何が変わったかを知る手段が無い。
GitHub のリリースノートを見に行く人はほとんどいない。
リリースノートは CHANGELOG.md の該当する版の節と同じ内容で（AGENTS.md の Release 節）、bot はそれを Discord 上で読めるようにするだけでよい。

## 依存 / 関連 change

- 後続: [リリース通知](../release-announcement/design.md) — 起動時に新しい版の変更点をチャンネルへ通知する。本 change の CHANGELOG の読み込み、節の切り出し、版の比較、表示の組み立てをそのまま使う

## Goals / Non-Goals

**Goals:**

- `/release-note [version]` で、任意の版（省略時は動いている版）の変更点を表示する
- CHANGELOG.md を bot のイメージに入れ、版ごとの節を正しく切り出す

**Non-Goals:**

- 起動時の通知（[リリース通知](../release-announcement/design.md) が扱う）
- GitHub の API やリリースページからノートを取ること

## Decisions

| 判断事項 | 選択 | 理由 |
| -------- | ---- | ---- |
| ノートの出どころ | イメージに同梱した `CHANGELOG.md` | リリースノートは CHANGELOG の節と同じ内容である。ネットワークや rate limit に依存しない。`.dockerignore` が `*.md` を除外しているので、`!CHANGELOG.md` を足して Dockerfile で `COPY` する |
| 節の切り出し | 版ごとの節は `## [x.y.z] - YYYY-MM-DD` の見出しから、次の `## [` の見出し、または git-cliff が末尾に出す注釈（`<!-- generated by git-cliff -->`）と比較リンクの定義（`[x.y.z]: https://...`）の前までとする。`[Unreleased]` は読まない。見出しは行頭のものだけを数え、コードブロックの中は無視し、CRLF も読める。同じ版の見出しが 2 つあれば、その版は壊れたものとして扱う。見出しの下に項目が 1 つも無い節は壊れておらず、「変更点の記載はありません」と表示する | 後続のリリース通知が、節の欠けや重複を検出して通知を止められるように、壊れた節を黙って読み飛ばさない |
| 版の表記 | 数値 3 つの `x.y.z` だけを扱う。入力の先頭の `v` は外して受け付ける。prerelease や build の付いた版は扱わない | この repository のリリースは `x.y.z` だけである。比較の規則を後続のリリース通知と共有する |
| 読み込みの時期 | 起動時に 1 回読み、プロセスの中で持つ | CHANGELOG はイメージと一緒にしか変わらない。ファイルが無い、または読めなければログに残し、`/release-note` は読めない旨の notice を返し、autocomplete は候補を返さない。bot の起動は止めない |
| 引数と autocomplete | 引数 `version` は任意で、CHANGELOG にある版を autocomplete で出す。入力中の文字列で全版を絞り込んでから、新しい順に 25 個まで返す。候補に出ない版も、入力すれば表示できる。省略時は動いている版（`package.json` の `version`） | autocomplete の候補は 25 個が上限で、CHANGELOG には 25 を超える版がある |
| 表示 | Components V2 の Container に `## DisQord v<版> の変更点` と節の本文を入れる。本文は見出しと footer の分を差し引いたうえで、チャット返信と同じ `splitTextIntoMessages`（`src/utils/chatContainerBuilder.ts`。文字数とバイト数の両方の上限を守る）でページに分け、2 ページ目以降は follow-up で送る。すべてのメッセージに `IsComponentsV2` の flag と `allowedMentions: { parse: [] }` を付ける | 日本語は 4000 字より前にバイト数の上限に届く。CHANGELOG の行は PR のタイトルそのままなので、`@everyone` やロールのメンションが入っていても通知しないようにする |
| 公開範囲 | 返信は ephemeral にしない | 他の人にも見せたい情報である |
| 見つからない場合 | 節が無い、壊れている、または CHANGELOG が読めなければ、その旨の notice を返す（ephemeral） | 利用者の入力の誤りを、チャンネルに残さない |

## Design

### 変更対象ファイル

- 新規: `src/services/releaseNotes.ts` — CHANGELOG の読み込み、節の切り出し、版の解析と比較、表示用のページの組み立て
- 新規: `src/bot/commands/releaseNote.ts` — `/release-note` の定義
- 修正: `src/bot/commands/index.ts` — コマンドの登録
- 修正: `src/bot/commands/handlers.ts` / `src/bot/events/interactionCreate.ts` — `/release-note` の handler と autocomplete
- 修正: `src/index.ts` — 起動時に CHANGELOG を読み、handler へ渡す
- 修正: `Dockerfile` / `.dockerignore` — `CHANGELOG.md` をイメージに入れる
- 修正: `scripts/preview/fixtures.ts` — `/release-note` の表示を preview に足す
- テスト: `tests/unit/services/releaseNotes.test.ts` ほか

### 節の切り出しの型

```ts
type ReleaseSection =
  | { version: Version; date: string; body: string; status: "ok" }
  | { version: Version; status: "duplicate" };

interface ReleaseNotes {
  /** 新しい順。 */
  versions(): Version[];
  section(version: Version): ReleaseSection | undefined;
}
```

後続のリリース通知は、範囲の中に `duplicate` があれば通知を止める。
本 change の `/release-note` は、`duplicate` を「壊れている」旨の notice にする。
