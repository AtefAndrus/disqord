# 発言者の区別と名前の見せ方

## Why

v1.15.0 では、モデルに渡す発言者の名前は、今回の発言ではサーバーのニックネーム、会話履歴では表示名（`global_name`）で、ユーザー名もユーザー ID も渡していない。
そのため、ニックネームを全員同じにしているサーバーでは、今回の発言者が毎回同じ名前に見え、履歴の同じ人とは別人に見える。
2026-10-17 の本番のスレッドでは、bot が今回の発言者全員をニックネームの名前で呼び、履歴の表示名の人と結び付けられなかった。

返答中の発言番号を置き換えたリンクにも、見せ方の問題が二つある。
bot 自身の発言へのリンクは「bot の発言」と表示される。
また、モデルがリンクの前後に発言者の名前を重ね、「[佐藤 の発言](…) の佐藤さんの発言」のような文になることがある。

## Goals / Non-Goals

**Goals:**

- 同じ表示名の人どうしを、モデルが発言者として区別できるようにする
- 同じ人の発言を、今回の発言と会話履歴とで同じ名前で渡す
- bot 自身の発言へのリンクの文字を、bot の名前にする
- 発言へのリンクの前後に、発言者の名前を重ねて書かせない

**Non-Goals:**

- サーバーのニックネームをモデルに渡すこと。履歴の発言は REST で読むのでニックネームが無く、取得にはメンバーごとの追加の呼び出しが要る
- ユーザー ID をモデルに渡すこと。ユーザー名で一意に区別でき、ID は利用者が読んでも誰か分からない

## Decisions

| 判断事項 | 選択 | 理由 |
| -------- | ---- | ---- |
| モデルに渡す名前 | 常に `表示名 (@ユーザー名)` の形にする。表示名が無いときは、ユーザー名を表示名の位置にも置く（`alice (@alice)`）。表示名の中の半角括弧は全角にする | ユーザー名は Discord 全体で一意なので、表示名が同じでも区別できる。表示名を残すのは、利用者がふだん呼び合う名前でモデルが呼べるようにするためである。表示名が無いときに `@alice` だけにすると、返答するかの判定に渡る `@alice: …` が alice への発言のように読める。表示名の括弧を全角にするのは、表示名で `佐藤 (@satou)` のように末尾の `(@ユーザー名)` をまねられないようにするためで、モデルへの指示でも末尾の `(@…)` だけがユーザー名だと伝える |
| ニックネーム | 今回の発言でも使わない | 履歴の発言はニックネームを持たないので、今回の発言だけに使うと同じ人が別の名前で渡る。返答するかの判定に渡す名前も同じ形にする |
| 名前の持ち方 | 名前は `authorNames()` 1 か所で組み立て、`NormalizedMessage` の `author` にモデル向けの名前、`displayName` にリンク用の表示名を持たせる | リンクの文字には表示名だけを使い、モデル向けの文字列にはユーザー名も付けるので、組み立てた後の文字列からは分けられない。組み立てを 1 か所にすると、履歴、今回の発言、判定で形がずれない |
| リンクの文字 | 人の発言は `<表示名> の発言`、bot 自身の発言は `<bot のサーバーでの表示名> の発言` | ユーザー名まで入れると、本文中のリンクが長くなって読みにくい。リンクを押せば誰の発言かは Discord で確かめられる。bot の名前は、返答するかの判定が使う名前（`message.guild.members.me?.displayName`）と同じにする |
| 名前の重複への対処 | 会話の発言を番号で指す指示（`buildConversationSafetyMessage()`）に、番号はそれ自体が「<発言者> の発言」と表示されるので、前後に発言者の名前や「の発言」を書かないことを、悪い例と良い例を添えて足す | 表示後の文から重複を取り除く処理は、日本語の言い回しが多様で誤って本文を削りうる。リンクの文字から発言者を外す案は、どの発言かを利用者が読めなくなり、番号をリンクにした目的に反する |

## Design

### 変更対象ファイル

- 修正: `src/utils/discordMessageNormalizer.ts` — 名前を組み立てる `authorNames()` を足す。`NormalizedMessage` の `author` をモデル向けの名前にし、リンク用の `displayName` を持たせる
- 修正: `src/bot/events/messageCreate.ts` — 今回の発言と返答するかの判定の名前を `authorNames()` で作り、ニックネームを使わない。bot の表示名をリンクの置き換えに渡す
- 修正: `src/services/conversationWindow.ts` — 発言番号の参照先に `displayName` を渡す
- 修正: `src/utils/messageRefLinks.ts` — リンクの文字に表示名を使い、bot 自身の発言は bot の表示名にする
- 修正: `src/services/chatService.ts` — `buildConversationSafetyMessage()` に、名前の形の説明と重複を避ける指示を足す
- 修正: `scripts/reply-gate-eval.ts` — 判定の評価が本番と同じ名前の形で状態を作るようにする。例は表示名だけを持つので、表示名ごとに決まった仮のユーザー名を付ける

`chatService.ts` の履歴と `[current]` の書式、`replyGateService.ts` の書式は `NormalizedMessage.author` と渡された名前をそのまま使うので、変えない。

### 実装内容

名前を組み立てる関数は、`normalizeAuthorLabel()` と同じく改行、制御文字、角括弧を取り除き、表示名とユーザー名をそれぞれ 32 文字までに切ってから組み合わせる。
表示名が空になったときはユーザー名を、ユーザー名も空になったときはユーザー ID を使う。

bot 自身の発言は、モデルへは今と同じく `assistant` のロールで渡し、名前は変えない。

モデルへの指示の例は次の形にする。

```text
悪い例: 一番古いのは [m1] の佐藤さんの発言で、
良い例: 一番古いのは [m1] で、
```

## Open Questions / Risks

- ユーザー名がモデルの入力に入る。OpenRouter を通じて各プロバイダに渡るので、表示名だけを渡していた今より、渡る情報が増える。
- 名前の重複を避ける指示は、守られるかがモデル次第である。`message-ref` の E2E は重複を検出しないので、手動確認で見る。
