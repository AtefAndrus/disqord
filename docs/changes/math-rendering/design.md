# 数式を画像で表示する

## Why

Discord は TeX の数式を描画しない。
数学の話題では、モデルが `\[ … \]` の別行立ての数式と `\( … \)` の文中の数式を多用し、返答は記号の並んだ読みにくいテキストになる。
別行立ての数式を画像にして本文の該当位置に差し込み、文中の数式は読めるコードの表記にする。

## 依存 / 関連 change

- 連携: [画像生成](../image-generation/design.md) — 同 change の planner（`ResponseLayoutPlanner`）が、返答のページに添付と `MediaGallery` を割り付ける契約と、編集で残す添付を明示する契約を持つ。本 change はその planner に「本文の位置に紐づく画像」を足す拡張として実装する。本 change を先に実装するときは、planner を同 change の仕様どおりに作ったうえで拡張する

## Goals / Non-Goals

**Goals:**

- 返答の本文の別行立ての数式（`$$ … $$` と `\[ … \]`）を PNG にし、最終描画のときに本文の該当位置へ `MediaGallery` で差し込む
- 文中の数式（`$ … $` と `\( … \)`）は、区切りの記号を外してインラインコードにする
- 画像の説明（alt）に元の TeX を入れ、会話の窓が bot の過去の返答を読み戻すときに数式を元の位置へ戻す
- 画像にできない数式は、TeX のコードブロックで表示する

**Non-Goals:**

- 文中の数式の画像化。Discord は文の途中に画像を置けない
- 生成中（ストリーミング中）の数式の描画。画像は最終描画のときに作る
- 数式を Unicode の記号（x²、√ など）へ変換すること。変換できる範囲が狭く、複雑な式では誤った表示になりうる

## Decisions

| 判断事項 | 選択 | 理由 |
| -------- | ---- | ---- |
| 数式の検出 | 本文を先頭から走査する小さな関数で、コードブロック（フェンス）、インラインコード（バッククォートの連なり）、バックスラッシュのエスケープ、数式の区切り（`$$`、`\[`、`\]`、`$`、`\(`、`\)`）を見分け、本文を「文章」と「別行立ての数式（TeX）」の並びに一度だけ分ける。文中の数式は文章の中に残し、範囲だけを印にする。コードの中と、区切りの `\` の前にバックスラッシュが奇数個続くもの（`\\[` は、エスケープされたバックスラッシュと `[` であり区切りではない）は数式にしない。`$` の文中の数式は pandoc と同じ規則にする。開きの `$` の直後は空白でなく、閉じの `$` の直前は空白でなく、閉じの `$` の直後は数字でない | 本文を数式の前後で区切るには、元の文字列のどこからどこまでが数式かが要る。ox-content（`@ox-content/napi`）の `parse` は数式とコードを正しく見分けたが、構文木に位置が無い。位置を含む `parseMdastRaw` は独自のバイナリ形式で、読み解く実装が公開パッケージから export されていない（`@ox-content/unplugin` の exports に無い）ので、内部の形式に依存するコードを写して持つことになる。見分ける対象は 4 種類だけなので、自前の走査をテストで固める方が保守しやすい。`$` の規則は、`$5 と $10` のような金額を数式にせず、`$2+2$` のような数式は数式にするためである。位置を持ち回らずに並びへ分けるのは、後の処理（文中の数式の置き換え、分割器の区切り線の置き換えと改行の正規化）が文字列を変えても、数式の区切りがずれないようにするためである |
| 描画 | MathJax 4（npm の `mathjax`）で TeX を SVG にし、resvg（`@resvg/resvg-js`）で PNG にする。SVG の `data-latex` 属性は PNG にする前に取り除く。フォントのファイルは用意しない | MathJax 4 の SVG 出力は、内蔵の数式フォントにある字形をパスで描く。2026-09-27 の試行で、分数、`\pmod`、`\tag`、`\boxed`、`cases` を 1 式あたり約 20ms で描けた。内蔵のフォントに無い文字は `<text>` 要素になり、フォントが無いと正しく描けないが、その数式はコードブロックにする（下の「画像にしない数式」）。MathJax 4 は `data-latex` に元の TeX を `<` をエスケープせずに入れ、resvg が SVG として読めずに失敗した（`cases` の `x<0`）。属性を取り除くと描けた |
| 描画の失敗の検出 | MathJax の出力に `merror` の節（`data-mml-node="merror"`）があれば失敗とする。例外と resvg の失敗も失敗とする | MathJax は不正な TeX でも例外を投げず、エラーの表示を数式の出力に埋め込む |
| 色と背景 | 白地に黒の文字で、周りに余白を付ける | 利用者のテーマ（ライトかダーク）を bot は知らない。透明の背景に明るい文字にすると、ライトテーマで読めない |
| 画像の大きさ | 2 倍の解像度で描く。描画の前に resvg で出来上がりの幅と高さを求め、幅が 1600px を超える式と高さが 800px を超える式は描かない。描いた PNG が 1 MiB を超える式も画像にしない | 横に長い式を縮めると読めなくなる。PNG の容量は描いた後にしか分からず、短い TeX でも大きな高さを指定できるので、描画の前に画素数を抑えて resvg のメモリの使用を制限する |
| ページの分割 | 分割器は「文章」と「別行立ての数式」の並びを受け取り、文章は今の規則で分け、数式は 1 つの塊として途中で切らない。文中の数式から作ったインラインコードも、途中で切らない塊として渡す。数式は、画像にできずコードブロックにしたときの文字数とバイト数でページの予算に数える。コードブロックは、前後の文章と改行で分け（前の文章が改行で終わっていなければ改行を足し、後ろの文章も改行から始める）、フェンスは TeX の中のバッククォートの連なりより長いバッククォート（3 個以上）に `tex` を付けたものにする。足した改行とフェンスも予算に数える。1 つの数式のコードブロックがページの予算を超えるときは画像にせず、本 change の側で TeX を行の境目でページの予算に収まる塊に分け、1 行がそれでも収まらないときはその行を文字の位置で分け、塊ごとに同じ長さのフェンスで囲む。文中の数式のインラインコードがそれだけでページの予算を超えるときは、インラインコードにせず、別行立ての数式と同じコードブロックにする | 今の分割器は文字数とバイト数で本文を切り、コードブロックだけを守るが、フェンスを常にバッククォート 3 個として扱い、インラインコードの開閉を追わない。数式の途中で切ると、どちらのページでも数式として検出できず、生の TeX が残る。描画の失敗や上限の超過は分割の後に分かるので、コードブロックにしてもページの予算を超えないよう、その大きさで先に数える。本 change が作る長いフェンスとインラインコードは、分割器の汎用の規則に任せず、塊として扱うか自ら分ける |
| 配置 | ページの本文を数式の位置で区切り、`TextDisplay` と、数式 1 つにつき 1 つの `MediaGallery` を交互に並べる。空の区切り（数式だけの返答、ページの先頭や末尾の数式）には `TextDisplay` を置かない。区切り線（`---`）だけの区切りは、今の区切り線の扱いと同じく `Separator` にする | `MediaGallery` に複数の画像を入れると横に並ぶ格子になり、式の順が読みにくい。今の組み立ては空の本文を「（応答なし）」に置き換えるので、数式の前後に偽の本文が出ないようにする |
| 上限 | ページごとに、component 40 個と添付 10 件を、`reasoning.md` と画像生成の生成物と合わせて数える。`reasoning.md` と生成物が先に使い、残りに収まる数だけ数式を先頭から画像にし、収まらない数式はコードブロックで表示する。添付の容量は、1 式 1 MiB の上限（上の「画像の大きさ」）で Discord の 1 ファイルの上限（既定 20 MiB）に十分収まる | Discord の 1 メッセージの上限である（[画像生成](../image-generation/design.md) の planner が確かめたもの）。数式の多い証明は 10 式を超えうる |
| 編集での添付と再試行 | 画像生成の planner の送信と編集の契約に従う。数式の画像も planner の生成物として扱い、編集では planner が残す添付を ID で、新しいファイルを `files` と `attachments`（`files[n]` の `n` を ID にしたもの）で明示する。最初の編集が失敗したときも、同 change の規則（メッセージを取得し直してファイル名で反映済みの添付を確かめ、未反映のものを 1 度だけ再試行する）に従う | Discord の API v10 の編集では、`attachments` に編集の後も残す添付を列挙し、今回送る新しいファイルもそこに含める必要がある。同じページに `reasoning.md`、生成物、数式の画像が同居しうるので、編集と再試行の規則を 2 つの change で分けず、planner の 1 か所に置く |
| 画像の説明と読み戻し | 数式の画像のファイル名を `math_<requestId>_<連番>.png` にし、`MediaGallery` の項目の説明に元の TeX を入れる。会話の窓は bot の返答を読み戻すとき、`MediaGallery` の項目の `media.attachment_id` をメッセージの `attachments[].id` と対応させてファイル名を得て、ファイル名が `math_` で始まる画像だけを数式とみなす。対応する添付が無い項目は数式とみなさない。そのうえで `TextDisplay`、`Separator`、数式の画像を並びの順に本文へ戻す（数式は `$$ … $$` にする）。TeX が UTF-16 の単位で 1024 を超える数式は画像にせず、コードブロックにする | 窓は今、bot の返答の `TextDisplay` と `Separator` だけを読むので、画像にした数式は窓から消え、次の応答のモデルが前の式を参照できなくなる。画像生成の生成物の説明はプロンプトなので、ファイル名で区別する。`MediaGallery` の項目にはファイル名の欄が無いので、添付の ID で結び付ける。説明は 1024 字までで、discord.js の検証は UTF-16 の単位（`string.length`）で数える |
| 画像にしない数式 | 描画の失敗、上の大きさや上限を超えるもの、描画の期限に間に合わないもの、SVG に `<text>` 要素を含むもの（内蔵の数式フォントに無い文字を含む。日本語やハングルなど）は、コードブロックで表示する | 数式の中の日本語は、MathJax 3 でも 4 でも正しい字形で描かれなかった（2026-09-27 の試行）。`<text>` の有無で判定すると、文字の種類を列挙せずに、フォントが無いと描けない数式をすべて外せる。ギリシャ文字や数学記号は内蔵のフォントがパスで描くので外れない |
| 文中の数式の表記 | 区切りを外し、中の改行を空白にして、中のバッククォートの連なりより長いバッククォートで囲むインラインコードにする。TeX の先頭か末尾がバッククォートなら、囲むバッククォートとの間に空白を 1 つ入れる | 数式の中にバッククォートや改行があると、単純な `` `…` `` ではインラインコードにならない。端のバッククォートは、空白で離さないと囲むバッククォートとつながって長さが変わる（CommonMark のコードスパンの規則） |
| モデルへの指示 | 書式の system メッセージ（`DISCORD_FORMAT_SYSTEM_MESSAGE`）に、別行立ての数式は `$$ … $$` か `\[ … \]` で書き、数式の中に日本語を入れず説明は式の外に書くよう足す | 日本語を含む数式は画像にできないので、モデル側で避けさせる |
| 描画の時間と停止 | 1 回の最終描画で、数式の描画に全体で 3 秒の期限を置く。数式を 1 つ描く前に期限を確かめ、過ぎていれば残りの数式をコードブロックにする。resvg の描画は同期の呼び出しで途中で止められないので、期限を超えうるのは描画中の 1 式分までであり、その 1 式の時間は「画像の大きさ」の上限で抑える。描画は生成が終わった後に行うので、描画中に停止ボタンが押されたときは、生成が終わった後の今の扱い（「既に完了している」旨を返す）と同じにする | 生成が終わると、停止の対象は外れるが、停止ボタンは最終描画の編集まで表示されている。描画の時間を短く抑え、ボタンが効かない時間を長くしない |
| 設定 | 設定の切り替えは作らず、常に有効にする | 費用が掛からず、数式が無い返答には何も起きない |

## Design

### 流れ

1. 最終描画の前に、本文を走査で「文章」と「別行立ての数式」の並びに分ける
2. 文章の中の文中の数式をインラインコードに置き換える
3. 分割器が、並びを受け取り、数式を塊として扱ってページに分ける
4. ページごとに、予算に収まる数式を PNG にし、収まらない数式と画像にしない数式をコードブロックにする
5. planner が、本文の区切りと数式の画像を交互に並べた `Container` を作り、添付と合わせて送信または編集する

### 変更対象ファイル

- 新規: `src/utils/mathSegments.ts` — 数式の範囲の走査、文中の数式の置き換え
- 新規: `src/utils/mathRenderer.ts` — TeX から PNG への描画（MathJax、`merror` の検出、`data-latex` の除去、resvg、大きさの確認）
- 修正: `src/utils/chatContainerBuilder.ts` — 分割器で数式とインラインコードを塊として扱う。最終描画の `Container` に、本文の区切りと `MediaGallery` を交互に並べ、空の区切りを置かない。編集の payload は planner の契約に合わせる
- 修正: planner（画像生成の `ResponseLayoutPlanner`）— 本文の位置に紐づく画像を割り付ける
- 修正: `src/bot/events/messageCreate.ts` — 最終描画で数式の画像を作り、添付として送る
- 修正: `src/utils/discordMessageNormalizer.ts` — bot の返答を読み戻すとき、数式の画像を説明から並びの順に本文へ戻す
- 修正: `src/services/chatService.ts` — 書式の system メッセージに数式の書き方を足す
- 修正: `package.json` / `Dockerfile` — `mathjax`、`@resvg/resvg-js` を足す。resvg はネイティブのバイナリを使う
- 修正: `scripts/preview/fixtures.ts` — 数式を含む返答の見本（`bun run preview` で見た目を確かめる）
