# 返答中の発言番号をメッセージリンクにする

## Why

会話履歴をモデルへ渡すとき、bot は各発言に `[m<N>]` の番号を付け（`src/services/chatService.ts:154`）、返信で届いた依頼には `(reply to [m<N>])` を付ける（`src/services/chatService.ts:182-184`）。
モデルはこの番号を返答にそのまま書くことがあり（例: 見出しの「m12 の補足」）、利用者には意味の分からない記号として表示される。
番号を表示するときに、その発言へ移動できるメッセージリンクに置き換えて、どの発言の話かを利用者が辿れるようにする。

## 依存 / 関連 change

- 関連: [会話履歴のツイートを読む tool](../history-tweet-tool/design.md) — どちらも発言番号を使う。互いに依存しない。

## Goals / Non-Goals

**Goals:**

- 返答の本文に角括弧付きで現れた、その返答でモデルに示した発言の番号（`[m<N>]`）を、その発言のメッセージリンクに置き換えて表示する。ストリーミング中、完了時、停止時、エラーで終わったときの途中表示のすべてに適用する。
- 推論表示（推論の TextDisplay と `reasoning.md`）にも同じ置き換えを適用する。
- モデルに、発言を指すときは `[m<N>]` の形で書くよう system メッセージで伝える。
- 長い返答をページに分けるとき、リンクが 2 ページにまたがって切れないようにする。

**Non-Goals:**

- 番号の付け方や、モデルに渡す履歴の形式の変更。
- その返答で示していない番号（モデルが作った番号など）の削除や言い換え。そのまま表示する。
- 角括弧の無い裸の番号（`m12`）の置き換え。理由は Decisions の「置き換える対象」に書いた。
- bot 自身の過去の返答を履歴として読み直すとき、本文のメッセージリンクを番号へ戻すこと。モデルにはリンクの URL がそのまま渡る。
- 定期実行の投稿。会話の窓を作らないので、番号が現れない。

## Decisions

| 判断事項 | 選択 | 理由 |
| -------- | ---- | ---- |
| 対処の方向 | 番号を表示時にメッセージリンクへ置き換える | 「番号を返答に書かない」と指示する案は、守られるかがモデル次第であり、守られた場合も利用者はどの発言の話かを辿れない。番号の形式を発言者名や時刻に変える案は、同じ人の発言が並ぶと一意にならず、全発言の分だけ入力トークンも増える |
| 置き換える対象 | 角括弧付きの `[m<N>]` だけで、その返答で示した番号に限る。次の位置にあるものは置き換えない: コードブロックとインラインコードの中、既存の Markdown のリンク（`[文字](URL)`）の範囲全体（`[m12](...)` も、`[補足 [m12]](...)` のように文字の中にある番号も含む）、生の URL と `<...>` で囲んだ URL の中、バックスラッシュでエスケープした開始の角括弧（`\[m12]`。直前のバックスラッシュが奇数個のとき） | 裸の `m<N>` は、示した番号に限っても、変数名や型番（`m3.medium` など）として書かれた同じ文字列と区別できず、返答の意味を変えてしまう。そのため、利用者に見えた例の裸の `m12` は、system メッセージの指示で `[m12]` と書かせることで扱い、指示が守られなかった分は番号のまま残る（Open Questions / Risks）。既存のリンクや URL の中を置き換えると、リンクが入れ子になったりリンク先が変わったりする。コードの中の文字列は、利用者が書いたとおりに見せる |
| リンクの形 | マスクリンク `[<発言者> の発言](https://discord.com/channels/<guild>/<channel>/<message>)`。発言者は履歴に渡した表示名（`NormalizedMessage.author`）、channel は発言自身のチャンネル ID とする。bot 自身の返答は発言者が `assistant` になるので（`src/utils/discordMessageNormalizer.ts:341`）、「bot の発言」とする | 2026-10-15 に Discord PTB で、Components V2 の TextDisplay に両方の形を置いて表示を確かめた。生の URL は「# 手動test › (吹き出しのアイコン)」のようなチップになり、押せば移動できるが、誰のどの発言かは表示されない。マスクリンクは「satou_jayo の発言」と青字で表示され、見出しの中でも崩れなかった。番号が利用者に分からないという問題に対しては、誰の発言かが読めるほうが合う |
| 置き換える場所 | 描画の直前、`splitTextIntoMessages()` に渡す前の本文。`messageCreate.ts` の完了、停止、エラー時の途中表示と、`streamingUpdater.ts` の描画 | 置き換え後の長さでページ分割させる（リンク 1 つで本文が約 100 文字増える）。モデルの出力そのもの（`updater.text`）は変えないので、usage の集計や停止時の受信文字数は今と同じ値になる |
| ページ境界とリンク | ページ分割で、Markdown のリンク（`[文字](URL)`）と生の URL を分割しない単位として扱う | 分割はコードポイント単位で切る（`src/utils/chatContainerBuilder.ts:112-160`）。2026-10-15 に `splitTextIntoMessages()` で、メッセージリンクの前に置く文字数を 1〜4099 文字、英字と日本語の 2 通りで変えて試すと、8198 通り中 115 通り（日本語の本文で 1 ページ目が満ちる位置）で URL が 2 ページに分かれ、どちらのページでもリンクとして働かなかった。本文の後ろに足す検索結果のリンクも同じ分割を通るので、この変更で一緒に直る |
| 番号の解決に使う情報 | `ConversationToolContext` に、番号から `{ messageId, channelId, author, kind }` を返す読み取り専用の操作を足す。`resolveMessageRef()`（`src/services/conversationWindow.ts:532-535`）と同じく、呼んだ時点の返答ごとの状態（`shown` と `pinShown`）を探す | `resolveMessageRef()` は発言 ID しか返さず、リンクの文字に要る発言者とチャンネルが分からない。返答ごとの状態は、`read_earlier_messages` やピン留めの読み取りで後から示した発言も含むので（`src/services/conversationWindow.ts:1076-1093`）、最初に組み立てた `conversation.messages` を探すだけでは足りない |
| モデルへの指示 | 会話履歴の安全指示（`buildConversationSafetyMessage()`）に「会話の発言を指すときは `[m12]` のように番号を角括弧で書く。表示時に『<発言者> の発言』というその発言へのリンクになる。角括弧の無い番号は利用者に意味が伝わらないので書かない」と足す | 置き換えるのは角括弧付きの番号だけなので、書き方を揃えさせる必要がある |
| 推論表示 | 置き換えた推論の文字列を `fitReasoning()` に渡し、推論を切り詰める位置もリンクの途中を避ける。収まらないリンクは丸ごと省き、全文は `reasoning.md` に残す | 推論の切り詰め（`src/utils/chatContainerBuilder.ts:692-711`）は本文のページ分割とは別の処理なので、ページ分割の変更だけではリンクが切れる |
| 会話履歴が無効なとき | 置き換えない | 番号を付けた履歴をモデルに渡していないので、置き換える番号が無い |

## Design

### 変更対象ファイル

- 新規: `src/utils/messageRefLinks.ts` — 本文中の番号をメッセージリンクに置き換える関数。コードブロックの判定は `markThematicBreaks()`（`src/utils/chatContainerBuilder.ts:488`）と同じ CommonMark の規則を使い、インラインコードも除く。
- 修正: `src/bot/events/messageCreate.ts` — 完了、停止、エラー時の途中表示で、分割の前に置き換える。推論表示にも適用する。
- 修正: `src/bot/events/streamingUpdater.ts` — ストリーミング中の描画で、分割の前に置き換える。置き換えの関数を引数で受け取る。
- 修正: `src/services/chatService.ts` — 会話履歴の安全指示に一文足す。
- 修正: `src/services/conversationWindow.ts`、`src/llm/tools/registry.ts` — 番号から発言の情報を返す操作を `ConversationToolContext` に足す。
- 修正: `src/utils/chatContainerBuilder.ts` — `splitMarkdownByCharsAndBytes()` の分割単位に、Markdown のリンクと生の URL を加える。1 つの単位が 1 ページの予算を超える場合だけ、今と同じくコードポイント単位で切る。

### 実装内容

置き換えの関数は、本文と「番号からリンクの文字と URL を返す関数」を受け取り、置き換えた本文を返す。
その関数は `messageCreate.ts` で、番号から発言の情報を返す操作とギルド ID から組み立てる。
番号を解決できなければ、その番号は元の文字列のまま残す。
リンクの文字に入れる発言者の表示名は、Markdown の記号（`[`、`]`、`*`、`_`、`` ` ``、`~`、`|`、`\`）をバックスラッシュでエスケープする。表示名は利用者が自由に付けられるので、エスケープしないとリンクの文字が途中で終わったり、書式として解釈されたりする。

ストリーミング中は、末尾が `[m1` のように途中までしか届いていない番号は置き換えず、次の描画で置き換わる。

## Open Questions / Risks

- 置き換えるのは角括弧付きの番号だけなので、モデルが指示に従わずに裸の `m12` を書いた分は、今と同じく番号のまま利用者に見える。e2e と運用で裸の番号がどれだけ残るかを観測し、多ければ指示の書き方を見直す。
