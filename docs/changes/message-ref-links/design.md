# 返答中の発言番号をメッセージリンクにする

## Why

会話履歴をモデルへ渡すとき、bot は各発言に `[m<N>]` の番号を付け（`src/services/chatService.ts:154`）、返信で届いた依頼には `(reply to [m<N>])` を付ける（`src/services/chatService.ts:182-184`）。
モデルはこの番号を返答にそのまま書くことがあり（例: 見出しの「m12 の補足」）、利用者には意味の分からない記号として表示される。
番号を表示するときに、その発言へ移動できるメッセージリンクに置き換えて、どの発言の話かを利用者が辿れるようにする。

## 依存 / 関連 change

- 関連: [会話履歴のツイートを読む tool](../history-tweet-tool/design.md) — どちらも発言番号を使う。互いに依存しない。

## Goals / Non-Goals

**Goals:**

- 返答の本文に現れた、その返答でモデルに示した発言の番号を、その発言のメッセージリンクに置き換えて表示する。ストリーミング中、完了時、停止時、エラーで終わったときの途中表示のすべてに適用する。
- 推論表示（推論の TextDisplay と `reasoning.md`）にも同じ置き換えを適用する。
- モデルに、発言を指すときは `[m<N>]` の形で書くよう system メッセージで伝える。

**Non-Goals:**

- 番号の付け方や、モデルに渡す履歴の形式の変更。
- その返答で示していない番号（モデルが作った番号など）の削除や言い換え。そのまま表示する。
- bot 自身の過去の返答を履歴として読み直すとき、本文のメッセージリンクを番号へ戻すこと。モデルにはリンクの URL がそのまま渡る。
- 定期実行の投稿。会話の窓を作らないので、番号が現れない。

## Decisions

| 判断事項 | 選択 | 理由 |
| -------- | ---- | ---- |
| 対処の方向 | 番号を表示時にメッセージリンクへ置き換える | 「番号を返答に書かない」と指示する案は、守られるかがモデル次第であり、守られた場合も利用者はどの発言の話かを辿れない。番号の形式を発言者名や時刻に変える案は、同じ人の発言が並ぶと一意にならず、全発言の分だけ入力トークンも増える |
| 置き換える対象 | 角括弧付きの `[m<N>]` と、前後が英数字でない裸の `m<N>` の両方。その返答で示した番号（`resolveMessageRef()` が発言 ID を返す番号）に限る。コードブロックとインラインコードの中は置き換えない | 利用者に見えた例は裸の `m12` だった。示した番号に限れば、`m1` のような普通の文字列を誤って置き換える範囲は、その返答の番号の数までに絞られる。コードの中の文字列は、利用者が書いたとおりに見せる |
| リンクの形 | 生の URL `https://discord.com/channels/<guild>/<channel>/<message>` で、channel には発言自身のチャンネル ID を使う | Discord のクライアントは、メッセージリンクを移動先の発言を示す表示にする（Components V2 の TextDisplay での表示は未確認。Tasks の手動確認）。マスクリンク `[表示名](URL)` は表示名を決める必要があり、文中のどこに置いても自然に読める表示名が無い |
| 置き換える場所 | 描画の直前、`splitTextIntoMessages()` に渡す前の本文。`messageCreate.ts` の完了、停止、エラー時の途中表示と、`streamingUpdater.ts` の描画 | 置き換え後の長さでページ分割させる（リンク 1 つで本文が約 80 文字増える）。モデルの出力そのもの（`updater.text`）は変えないので、usage の集計や停止時の受信文字数は今と同じ値になる |
| 番号の解決に使う情報 | `messageCreate.ts` がすでに持つ `conversation.toolContext.resolveMessageRef()`（`src/bot/events/messageCreate.ts:470`）と、発言の `channelId`、ギルド ID | 番号と発言 ID の対応は返答ごとの状態にあり、Discord 操作の tool も同じ関数で番号を解決している。新しい状態を持たない |
| モデルへの指示 | 会話履歴の安全指示（`buildConversationSafetyMessage()`）に「会話の発言を指すときは `[m12]` のように番号を角括弧で書く。表示時にその発言へのリンクになる」と足す | 書き方を揃えると、置き換えの判定を角括弧付きの形に寄せられる。裸の番号も置き換えるので、指示が守られなくても表示は崩れない |
| 会話履歴が無効なとき | 置き換えない | 番号を付けた履歴をモデルに渡していないので、置き換える番号が無い |

## Design

### 変更対象ファイル

- 新規: `src/utils/messageRefLinks.ts` — 本文中の番号をメッセージリンクに置き換える関数。コードブロックの判定は `markThematicBreaks()`（`src/utils/chatContainerBuilder.ts:488`）と同じ CommonMark の規則を使い、インラインコードも除く。
- 修正: `src/bot/events/messageCreate.ts` — 完了、停止、エラー時の途中表示で、分割の前に置き換える。推論表示にも適用する。
- 修正: `src/bot/events/streamingUpdater.ts` — ストリーミング中の描画で、分割の前に置き換える。置き換えの関数を引数で受け取る。
- 修正: `src/services/chatService.ts` — 会話履歴の安全指示に一文足す。

### 実装内容

置き換えの関数は、本文と「番号から発言の URL を返す関数」を受け取り、置き換えた本文を返す。
URL を返す関数は `messageCreate.ts` で、`resolveMessageRef()` と発言のチャンネル ID、ギルド ID から組み立てる。
番号を解決できなければ、その番号は元の文字列のまま残す。

ストリーミング中は、末尾が `[m1` のように途中までしか届いていない番号は置き換えず、次の描画で置き換わる。

## Open Questions / Risks

- ページの分割はコードポイント単位で切るので（`src/utils/chatContainerBuilder.ts:112-160`）、リンクの URL がページの境界で切れる可能性がある。本文の後ろに足す検索結果のリンクも同じ条件にある。リンクを分割しない単位として扱う変更は、この change に含めるかを実装時に判断する。
- Components V2 の TextDisplay で、生のメッセージリンクが通常のメッセージと同じ表示になるかは確認していない。手動確認で表示が読みにくければ、マスクリンクに切り替える。
