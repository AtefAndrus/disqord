# スラッシュコマンドの返信の Components V2 化と /status の切り替えボタン

## Why

チャットの返信は Components V2 で描画しているが、`/help`、`/model`、`/config`、`/status` とボタンの返信は embed のままだった。
`/status` は設定値の一覧の下に別のボタンの行を並べていて、どのボタンがどの設定かが離れて見え、切り替えられる設定も 2 つに限られていた。

## Decisions

| 判断事項 | 選択 | 理由 |
| -------- | ---- | ---- |
| 返信の形 | すべての返信を Components V2 の Container にする。成功は BLURPLE の Container、エラーは既存の `buildErrorContainer` を使う | チャットの返信と同じ部品と見た目にそろえる |
| `/status` の切り替え | on/off の設定ごとに Section を置き、右側のボタンで反対の値に設定する。ボタンの custom ID は設定する値を持つ（`status_set:<key>:on\|off`） | Discord のメッセージにはトグルスイッチの部品が無い（チェックボックスはモーダルの中だけ）。値を持たせると、すばやく 2 回押しても元に戻らない |
| ボタンの権限 | Web 検索、ツイート展開、会話履歴のボタンは、対応する `/config` と同じく「サーバーの管理」権限を要る。無料モデル限定と LLM 詳細表示のボタンは、対応する `/config` と同じく権限を問わない | 同じ設定を変える経路で権限をそろえる |
| 設定エラーの表示 | 設定エラーは、スラッシュコマンドとボタンのどちらでも ephemeral にしない | 経路によって見え方が変わらないようにする |
| レート制限 | `/status` に表示しない | 利用者が見て取れる行動が無い |
| 項目の書き方 | 各項目を「項目名」と「値」の 2 行で書き、項目ごとに別の TextDisplay にする | 1 行に並べると名前と値の境目が分かりにくく、項目を分けると間隔が空いて見分けやすい |
| 古いボタン | 以前の `/status` のメッセージに残る `status_toggle_free_only` と `status_toggle_llm_details` も処理し、押されたら新しい表示に置き換える | 既に投稿されたメッセージのボタンを壊さない |
